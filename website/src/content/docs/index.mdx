## Why chord-gateway

<CardGrid>
  <Card title="7 IM platforms" icon="external">
    Connect WeChat iLink, Feishu, Telegram, WeCom, DingTalk, Discord, or Slack to `chord headless` and control Chord from an IM chat, including mobile devices.
  </Card>
  <Card title="Local-first" icon="seti:lock">
    Chord processes, workspace files, runtime state, and credentials stay on your machine or server.
    Chat messages still pass through the selected IM platform, and model-provider data handling follows your Chord configuration.
  </Card>
  <Card title="Per-chat isolation" icon="document">
    Pair one trusted owner per platform and explicitly bind each chat to a local directory.
    Gateway routes by workspace, IM type, and chat ID so different chats keep separate pinned Chord sessions.
  </Card>
  <Card title="Interactive approvals" icon="rocket">
    Confirmations, questions, todo updates, and session commands are surfaced back into the chat workflow.
  </Card>
</CardGrid>

## Get started

<CardGrid>
  <Card title="1. Install" icon="seti:go">
    ```bash
    go install github.com/keakon/chord-gateway@latest
    ```
    Install [Chord](https://github.com/keakon/chord#three-step-setup) separately and make sure `chord` is on `PATH`, or set `chord_path` in the gateway config.
  </Card>
  <Card title="2. Choose an IM platform" icon="random">
    Start with [WeChat iLink](/chord-gateway/wechat/), [Feishu](/chord-gateway/feishu/), [Telegram](/chord-gateway/telegram/), [WeCom](/chord-gateway/wecom/), [DingTalk](/chord-gateway/dingtalk/), [Discord](/chord-gateway/discord/), or [Slack](/chord-gateway/slack/), then keep only the adapter you need in `config.yaml`.
  </Card>
  <Card title="3. Run the gateway" icon="seti:powershell">
    ```bash
    chord-gateway -f config.yaml --pair
    ```
    Follow your platform's guide to bind and verify a directory in a private bot chat using the terminal's pairing code. Your first task starts Chord; later starts do not need `--pair`.
  </Card>
</CardGrid>
